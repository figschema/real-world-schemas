# MediaWiki database schema

>![MediaWiki database schema - ER diagram](schema.svg)

The database behind Wikipedia and every other wiki farm running MediaWiki: 64 tables, zero foreign keys, revision content split across a cluster of purpose-built tables - and the namespace system that shapes everything.

## What's interesting

- **One schema, every database.** MediaWiki maintains a dialect-neutral abstract schema (`tables.json`) and compiles it per database engine at install time - this capture is the MySQL rendering. The JSON even carries per-column documentation comments, which is why the dictionary reads so well.
- **The namespace system is structural.** Page titles are split into `page_namespace` + `page_title` everywhere, and link tables like `pagelinks`, `templatelinks`, and `categorylinks` carry `*_namespace` columns of their own - the schema models "what kind of page" as data, not as a string parse.
- **Revision content is layered.** `revision` → `slots` → `content` - a page's content is composed of named slots (main, plus, on some wikis, others), each versioned independently. The MediaWiki 1.3x content-model refactor is visible in the table structure.
- **Actors, not users.** The `actor` table maps both registered users and anonymous IPs to one integer ID, so every attribution column in the schema works identically for logged-in and logged-out contributors.
- **Zero foreign keys, MyISAM ghost included.** Like WordPress, integrity lives in PHP - and the `searchindex` table still declares `ENGINE=MyISAM`, a fossil of the era when MySQL fulltext search was the only option.
- **Prefix indexes everywhere.** Indexes like `bt_address(42)` and `el_to_domain_index_to_path(...,60)` truncate long text columns to fixed byte widths - hand-tuned InnoDB index-prefix budgeting, visible in the DDL.
