## Extraction

The schema is generated by Matomo's own schema class - `core/Db/Schema/Mysql.php`, whose `getTablesCreateSql()` returns the exact CREATE TABLE statements the installer executes:

1. Download `core/Db/Schema/Mysql.php` from the pinned release tag (GitHub contents API):

   ```
   curl -fsSL "https://api.github.com/repos/matomo-org/matomo/contents/core/Db/Schema/Mysql.php?ref=5.14.2" ...
   ```

2. Run it through a standalone PHP shim (any PHP 8 CLI; `extract.php` lives in this folder). The shim stubs the three infrastructural dependencies with their REAL shipped values - `Db\Settings` defaults (prefix `matomo_`, InnoDB, utf8mb4), `UsersManager\Model::MAX_LENGTH_TOKEN_DESCRIPTION = 100`, `Concurrency\Lock::MAX_KEY_LEN = 70` - then calls `getTablesCreateSql()` and mirrors the installer's own flow (`createTables()`), which **skips `archive_blob` and `archive_numeric`** (the archiver creates dated archive tables lazily):

   ```
   php extract.php work/Mysql.php > work/matomo-5.14.2.sql
   ```

3. Derived stats, counted from `work/matomo-5.14.2.sql` on 2026-10-31: **26 tables · 226 columns · 0 foreign keys**. Every statement carries `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4`; all tables carry the `matomo_` prefix. This is the CORE schema - bundled plugins add their own tables at install time, outside `Mysql.php`.

Rules: the downloaded `Mysql.php` (GPL) and the raw DDL stay in `work/` (gitignored) - only this provenance file, `extract.php`, the renders, and verified counts are published.

Alternative reproduction path: install Matomo against MySQL and `mysqldump --no-data` - the core table set matches (plugin tables included in the dump come from each plugin's own schema).
