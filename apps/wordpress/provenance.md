## Extraction

The schema is generated by WordPress' own installer code, not inferred from a template:

1. Download `wp-admin/includes/schema.php` from the pinned release tag:

   ```
   curl -fsSL -o work/schema.php \
     https://raw.githubusercontent.com/WordPress/WordPress/7.1.3/wp-admin/includes/schema.php
   ```

2. Run it through WordPress' own schema generator with a standalone PHP shim (any PHP 8 CLI; `extract.php` lives in this folder):

   ```
   php extract.php work/schema.php > work/wp-7.1.3.sql
   ```

   The shim defines `is_multisite()` (single-site install) and a minimal `$wpdb` - `wp_` table prefix, `get_charset_collate()` returning `DEFAULT CHARACTER SET utf8mb4`. The output is the exact `CREATE TABLE` set a fresh single-site install executes.

3. Derived stats, counted from `work/wp-7.1.3.sql` on 2026-10-23: **12 tables · 0 foreign keys · 41 key/index declarations**. The DDL pins no `ENGINE` - the storage engine comes from the server default (InnoDB on any modern MySQL/MariaDB).

Rules: the downloaded `schema.php` (GPL) and the raw DDL stay in `work/` (gitignored) - only this provenance file, the renders, and verified counts are published.

Alternative reproduction path: install WordPress normally (any host or local stack) and `mysqldump --no-data` - the resulting table set matches.
